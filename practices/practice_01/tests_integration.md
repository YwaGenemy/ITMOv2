# Integration-проверки

## Базовый план P1

Работающего API здесь нет. Ниже - план проверок на ASGI-приложении с fake LLM, а не результаты запуска. Требования: [правила кейса](context.md#факты-и-правила); предлагаемые коды ошибок: [Context Pack](context.md#формат-входа-и-результата).

| ID | Связь компонентов | Как воспроизводим | Ожидаемый результат | Подтверждение |
|---|---|---|---|---|
| I-01 | API → Service | JSON без diff, fake LLM считает вызовы | 422, вызовов 0 | План, не запускалось |
| I-02 | API → Service | 20001 символ в diff | 413, вызовов 0 | План |
| I-03 | Service → LLM | Синтетический пароль в diff | Fake видит замену вместо пароля | План |
| I-04 | Adapter → API | Fake выбрасывает ошибку | Контролируемая ошибка 502 | План |
| I-05 | LLM → validator → API | Fake возвращает 4 риска | 502 invalid_llm_output | План |

## Ограничения базового плана

Пока недостаточно подробно описаны fixtures, граница 20000/20001, полная цепочка логирования, deadline и способ независимой проверки. Этот артефакт выбран для шести экспериментов Практики 2. Дополнения по экспериментам будут отмечены их ID, базовый текст сохраняется для сравнения.
