**1. Явные вопросы проверки**

1. Требование API-1 предписывает обрезать diff длиннее 20 000 символов или отклонять его?
2. Автоматическое экранирование/санитизация секретов в diff гарантирует защиту от prompt injection?
3. Отсутствие блоков `try/except` в самом diff证明ет, что в приложении нет логирования ошибок?
4. Все ошибки внешнего LLM должны возвращаться клиенту как HTTP 500?

---

**2. Ответы по CASE / Context Pack**

| Вопрос | Ответ (источник) | Статус |
|---|---|---|
| 1. Обрезка vs отклонение | **Отклонение с HTTP 413 без обрезки и без вызова модели** (CASE.md: API-1; context.md: «HTTP 413 — более 20 000 символов, без обрезания и без вызова модели») | Нормативное требование |
| 2. Гарантия отсутствия prompt injection | **Нет. Санитизация секретов не решает prompt injection: diff отделяется от инструкций как недоверенные данные, модель не получает инструменты** (context.md: «Ограничения и запрещённые действия»). Полнота детектора секретов не доказана. | Проектное решение / известное ограничение |
| 3. try/except в diff ⇒ нет логирования в приложении | **Неверный вывод.** В diff может не быть try/except, а логирование может быть в middleware, глобальных обработчиках или адаптере LLM (OBS-1 требует логировать request_id, длительность, статус; CASE.md не запрещает логирование в сервисе). | Неизвестно / требует runtime-проверки |
| 4. Все ошибки LLM → HTTP 500 | **Нет.** Context Pack задаёт дифференцированные коды: timeout → 504, provider error / invalid output → 502, busy → 503. Только 413 зафиксирован в CASE; остальные — проектные решения. | Проектное решение (Context Pack) |

**3. Исправленный абзац для tests_integration.md**

> **Ограничения базового плана (исправлено)**
>
> - **I-02:** при diff > 20 000 символов сервис возвращает **413 без обрезки** и без вызова модели (API-1, нормативное требование).
> - **I-03:** санитизация секретов **не гарантирует** защиту от prompt injection; diff передаётся как недоверенные данные, модель без инструментов (Context Pack, известное ограничение).
> - Отсутствие `try/except` в diff **не доказывает** отсутствие логирования в приложении; логирование может быть в middleware/адаптере (OBS-1, требование логировать request_id, длительность, статус).
> - Ошибки LLM мапятся на **504 (timeout), 502 (provider error / invalid output), 503 (busy)** — не единый 500 (Context Pack, проектные решения).
>
> План дополнен этими уточнениями; базовый текст сохранён для сравнения с экспериментами Практики 2.
