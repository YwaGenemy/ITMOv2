# Few-shot

Цель: заменить общие формулировки базового плана проверяемыми случаями API-1 и SEC-1. Хороший и плохой образцы включены в запрос.

- Инструмент / модель: OpenCode CLI 1.18.31, `opencode/nemotron-3-ultra-free`, agent plan.
- Session: `ses_f39ee7c5cffewyAGcNNmaegl8f`. Реальный запуск, код завершения 0.
- Исходный артефакт: [tests_integration.md](../../practice_01/tests_integration.md); его состояние на момент запроса включено в [request.md](evidence/request.md).

## Запрос

````prompt
Русский язык, до 350 слов. Верни только итоговый ответ без скрытых рассуждений. Не используй инструменты, web, shell и не меняй файлы. Это план тестов будущего сервиса; не утверждай, что они выполнены. Нормативный источник — CASE, статусы кроме 413 — проектные решения Context Pack.

Техника Few-shot. Улучши integration-план: предложи три строки по образцу для длины 20000/20001 и SEC-1.
Хороший пример: «I-X | API → сервис → fake LLM | JSON {} | 422; fake.calls=0 | План, не запускалось».
Плохой пример: «Проверить, что валидация работает».
Для каждого случая укажи точный вход, настройку fake и наблюдаемый результат. Не предлагай просто добавить код.

````

Полный запрос со снимками источников: [request.md](evidence/request.md).

## Что получили

Модель предложила три случая: 20000 символов, 20001 символ и синтетический секрет. Для каждого указала HTTP-статус и число вызовов fake.

Полный ответ: [response.md](evidence/response.md). Журнал запуска: [run.json](evidence/run.json).

## Примеры

Хороший: конкретный JSON, HTTP-статус и число вызовов fake. Плохой: «проверить, что валидация работает». Модель перенесла формат образца на три новых сценария.
