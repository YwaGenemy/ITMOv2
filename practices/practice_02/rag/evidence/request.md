# Учебный кейс: AI-помощник ревьюера PR

На паре все работают с одним и тем же учебным diff, но каждый студент изменяет файлы в своём форке. Реальный PR с кодом для эксперимента не нужен: его роль выполняет `TRAINING_PR.diff`.

## Что открыть

- [`TRAINING_PR.diff`](TRAINING_PR.diff) — вход для обоих запусков;
- [`prompts.md`](prompts.md) — журнал двух запусков, master prompt и ваша проверка;
- [`context.md`](context.md) — факты и источники для Context Pack.

На занятии используем OpenCode по инструкции [`OPENCODE_SETUP.md`](../../OPENCODE_SETUP.md). Браузерный чат — только запасной вариант, если преподаватель подтвердил проблему с доступом.

## Запуск 1: только diff

1. Из корня своего форка откройте новую сессию OpenCode.
2. Останьтесь в режиме анализа: не разрешайте web, shell и изменение файлов.
3. Прикрепите **только** `TRAINING_PR.diff`.
4. Отправьте запрос:

```text
Ниже diff учебного PR. Посмотри PR и найди проблемы.
```

5. В `prompts.md` сохраните:
   - название инструмента и модели;
   - запрос;
   - краткий результат;
   - три слабых места ответа;
   - какой информации модели не хватило.

Если OpenCode не запускается, позовите преподавателя. Не переходите в другой интерфейс самостоятельно: сравнивать нужно два запроса с контролируемым входом, а не возможности разных агентов.

## Что такое master prompt

Master prompt — полный контракт выполнения задачи AI-агентом. Он отвечает на восемь вопросов:

1. Какова цель и в какой роли работает агент?
2. Какие входы и источники ему доступны?
3. Что именно нужно сделать и какие артефакты вернуть?
4. В каком формате давать результат?
5. Какие действия разрешены и запрещены?
6. По каким шагам работать и когда остановиться?
7. Как проверить утверждения и результат?
8. По каким признакам задача считается законченной?

Context Pack — промежуточная часть master prompt: отобранные факты, правила, примеры и ограничения для одной задачи. Он не заменяет цель, формат, рабочий процесс, проверки и Definition of Done.

## Материалы для Context Pack

После первого запуска прочитайте правила ниже. В Context Pack перенесите только те пункты, которые влияют на этот PR.

### Задача помощника

Для одного PR помощник получает diff и возвращает:

1. краткое описание изменения;
2. не больше трёх рисков с файлом, строкой и доказательством;
3. список проверок, которые стоит запустить.

Решение всегда принимает человек. Помощник не может approve, merge или менять код.

### Правила репозитория

- `SEC-1`: перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи.
- `API-1`: diff длиннее 20 000 символов отклоняется с HTTP 413.
- `REL-1`: внешний LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ.
- `OUT-1`: ответ содержит `summary`, массив `risks` и массив `checks`. В `risks` максимум три элемента с полями `file`, `line`, `evidence`, `risk`.
- `SCOPE-1`: сервис только советует; он не пишет код и не выполняет действия в GitHub.
- `QA-1`: риск включается в ответ, только если он подтверждён строкой diff или правилом репозитория.
- `OBS-1`: в лог пишутся только `request_id`, длительность и статус. Содержимое diff и ответа модели не логируется.

Эти правила не относятся к учебному PR и не должны попадать в Context Pack:

- таблицы базы данных называются в `snake_case`;
- все frontend-строки проходят через i18n.

### Примеры комментария

Хороший:

```text
app/review_service.py:16 — diff отправляется во внешний LLM без удаления секретов,
что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться,
что в prompt осталось [REDACTED].
```

Плохой:

```text
Код можно улучшить. Добавьте тесты и обработку ошибок.
```

## Запуск 2: тот же diff и master prompt

1. Используйте тот же инструмент и по возможности ту же модель.
2. Снова приложите `TRAINING_PR.diff`.
3. Передайте `Master Prompt v1` из `prompts.md`; внутри него используйте собранный Context Pack и ссылки на связанные артефакты.
4. Не добавляйте новые факты устно во время запуска.
5. Сравните ответы по четырём признакам:
   - есть ссылка на конкретный файл или строку;
   - вывод подтверждён diff или правилом;
   - соблюдены границы помощника;
   - указана воспроизводимая проверка.

Оценивается не «красота» второго ответа, а конкретная разница между двумя контролируемыми запусками и ваша собственная проверка результата.

## Context Pack для первого рабочего сценария

### Факты и правила

Источник всех обязательных правил — [CASE.md, «Правила репозитория»](CASE.md#правила-репозитория).

| ID | Требование |
|---|---|
| SEC-1 | Удалить токены, пароли и приватные ключи до передачи diff внешнему LLM |
| API-1 | При длине diff больше 20 000 символов вернуть HTTP 413 |
| REL-1 | Ограничить внешний вызов 10 секундами, контролируемо обработать ошибку |
| OUT-1 | Ответ: summary, risks, checks; максимум три риска с file, line, evidence, risk |
| SCOPE-1 | Только советы, без изменения кода и действий в GitHub |
| QA-1 | Каждый риск подтверждён строкой diff или правилом |
| OBS-1 | Логировать только request_id, длительность и статус; исключить diff и ответ LLM |

### Формат входа и результата

Проектное решение: POST /api/reviews, JSON `{"diff": "..."}`. Diff — непустая строка; длина считается в Unicode code points после JSON-декодирования. HTTP 422 — неверный тип, отсутствие поля или пустая строка. HTTP 413 — более 20 000 символов, без обрезания и без вызова модели.

Успех: `{"summary":"...","risks":[],"checks":[]}`. Каждый risk содержит file (строка), line (целое >= 1), evidence (строка), risk (строка). checks — массив строк. Неверная схема LLM, включая более трёх рисков, даёт 502. Timeout даёт 504; прочая ошибка провайдера — 502. Ошибки: `{"error":{"code":"llm_timeout"},"request_id":"..."}`; для остальных случаев code — invalid_request, diff_too_large, llm_failed, invalid_llm_output или busy. Код busy соответствует 503. Эти статусы, кроме 413, — проектные решения, а не цитаты из CASE.

### Ограничения и запрещённые действия

Ревьюер сам оценивает корректность совета. Сервис не получает GitHub write-токен. Секреты заменяются на `[REDACTED]` с сохранением строк. Санитизация секретов не решает prompt injection: diff отделяется от инструкций как недоверенные данные, модель не получает инструменты. Полнота распознавания произвольных секретов не доказана.

### Хороший пример

«В показанном методе diff включается в prompt до какой-либо очистки. Это противоречит SEC-1. Проверка: отправить синтетический секрет и убедиться через fake LLM, что prompt содержит `[REDACTED]`, а не исходное значение».

### Плохой пример

«В проекте нет авторизации» — это нельзя заключить по двум фрагментам без конфигурации middleware.

### Что пока неизвестно

Реальные пользователи, baseline времени ревью, провайдер и бюджет production, глобальные обработчики, полнота детектора секретов. Вход учебный; рабочий сервис и результаты runtime-тестов отсутствуют. [ADR](adr.md) описывает предлагаемый TO BE.
