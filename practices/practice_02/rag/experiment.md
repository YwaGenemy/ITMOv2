# RAG

Вопрос: какие проверки обязательных правил отсутствуют в базовом integration-плане? Retrieval: локально отобраны CASE.md, context.md и исходный tests_integration.md; снимки включены в запрос.

- Инструмент / модель: OpenCode CLI 1.18.31, `opencode/nemotron-3-ultra-free`, agent plan.
- Session: `ses_f39edb965ffe8s44eVZZcYDKZj`. Реальный запуск, код завершения 0.
- Исходный артефакт: [tests_integration.md](../../practice_01/tests_integration.md); его состояние на момент запроса включено в [request.md](evidence/request.md).

## Запрос

````prompt
Русский язык, до 350 слов. Верни только итоговый ответ без скрытых рассуждений. Не используй инструменты, web, shell и не меняй файлы. Это план тестов будущего сервиса; не утверждай, что они выполнены. Нормативный источник — CASE, статусы кроме 413 — проектные решения Context Pack.

Техника RAG: используй только отобранные и включённые ниже локальные источники CASE.md, context.md и tests_integration.md. Retrieval выполнен локальным чтением этих файлов; внешняя сеть и vector DB не нужны.
Вопрос: какие проверки SEC-1, API-1, REL-1, OUT-1, OBS-1 нужны на стыках компонентов и какие из них ещё не покрыты базовым планом?
Верни матрицу правило → конкретный проверяемый результат → ссылка на файл и заголовок источника. Раздели требование CASE и решение Context Pack. Не приписывай CASE конкретные HTTP-коды кроме 413. Для OBS-1 учти слои middleware/SDK, а не только logger сервиса.

````

Полный запрос со снимками источников: [request.md](evidence/request.md).

## Что получили

Модель составила матрицу SEC-1, API-1, REL-1, OUT-1 и OBS-1. Обнаружены пробелы в проверках timeout, схемы ответа и логов. Слово «покрыто» в ответе означало наличие пункта в плане, не результат теста.

Полный ответ: [response.md](evidence/response.md). Журнал запуска: [run.json](evidence/run.json).
