# R.C.T.F.

Role: QA; Context: REL-1 и неполный integration-план; Task: различить timeout, ошибку провайдера и схемы; Format: таблица fixtures/ожиданий/замера.

- Инструмент / модель: OpenCode CLI 1.18.31, `opencode/nemotron-3-ultra-free`, agent plan.
- Session: `ses_f39ee749effeDb8j4JT0Q5wTP5`. Реальный запуск, код завершения 0.
- Исходный артефакт: [tests_integration.md](../../practice_01/tests_integration.md); его состояние на момент запроса включено в [request.md](evidence/request.md).

## Запрос

````prompt
Русский язык, до 350 слов. Верни только итоговый ответ без скрытых рассуждений. Не используй инструменты, web, shell и не меняй файлы. Это план тестов будущего сервиса; не утверждай, что они выполнены. Нормативный источник — CASE, статусы кроме 413 — проектные решения Context Pack.

Техника R.C.T.F.
Role: инженер QA, проверяющий границу адаптер → API.
Context: integration-план ниже недостаточно описывает REL-1. Нужны timeout всего вызова 10 секунд, отмена работы, отсутствие retry, отличимые timeout/ошибка провайдера/ошибка схемы. Статусы 504/502 — решения Context Pack.
Task: предложи 3 интеграционных сценария, включая восстановление после timeout; не путай virtual clock unit-тест и реальный timeout интеграции.
Format: таблица ID, fixture, действие, ожидаемый HTTP и побочный эффект, способ замера. Нагрузочный допуск API 11 секунд — гипотеза стенда, а не изменение deadline адаптера.

````

Полный запрос со снимками источников: [request.md](evidence/request.md).

## Что получили

Получены сценарии timeout, ошибки провайдера и неверного формата ответа. Проверка восстановления после timeout была пропущена; она добавлена при редактировании.

Полный ответ: [response.md](evidence/response.md). Журнал запуска: [run.json](evidence/run.json).

## Оценка результата

Модель различила три причины отказа, но не добавила запрошенное восстановление после timeout. При редактировании сценарий дополнен последующим успешным запросом.
