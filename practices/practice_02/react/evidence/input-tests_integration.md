# Integration-проверки

## Базовый план P1

Работающего API здесь нет. Ниже — план проверок на ASGI-приложении с fake LLM, а не результаты запуска. Требования: [CASE.md](CASE.md#правила-репозитория); предлагаемые коды ошибок: [Context Pack](context.md#формат-входа-и-результата).

| ID | Связь компонентов | Как воспроизводим | Ожидаемый результат | Evidence |
|---|---|---|---|---|
| I-01 | API → Service | JSON без diff, fake LLM считает вызовы | 422, вызовов 0 | План, не запускалось |
| I-02 | API → Service | 20001 символ в diff | 413, вызовов 0 | План |
| I-03 | Service → LLM | Синтетический пароль в diff | Fake видит замену вместо пароля | План |
| I-04 | Adapter → API | Fake выбрасывает ошибку | Контролируемая ошибка 502 | План |
| I-05 | LLM → validator → API | Fake возвращает 4 риска | 502 invalid_llm_output | План |

## Ограничения базового плана

Пока недостаточно подробно описаны fixtures, граница 20000/20001, полная цепочка логирования, deadline и способ независимой проверки. Этот артефакт выбран для шести экспериментов Практики 2. Дополнения ниже будут отмечены ID экспериментов; базовый текст сохраняется для сравнения.

## P2-01 Few-shot

Дополнение по [эксперименту Few-shot](../practice_02/few_shot/experiment.md). Fake возвращает заранее заданный корректный OUT-1 JSON; выражение умножения строки ниже — способ создать Python fixture, не буквальный JSON.

| ID | Вход и fixture | Наблюдаемый результат | Статус |
|---|---|---|---|
| I-FS-01 | Создать payload dict(diff="x" * 20000), сериализовать HTTP-клиентом | 200, fake.calls=1, поля summary/risks/checks | План |
| I-FS-02 | Аналогично, 20001 символ | 413, fake.calls=0; исходный diff не обрезается | План |
| I-FS-03 | Синтетический fixture password=TEST_ONLY_SECRET; соответствующий шаблон детектора задан явно | В перехваченном prompt нет TEST_ONLY_SECRET, есть [REDACTED]; fake.calls=1, ответ 200 | План |

Дополнительно повторить границу с не-ASCII символами: измеряется декодированная строка, не размер UTF-8. Контракт не требует синтаксического парсинга git patch, поэтому строка x допустима для теста длины.

## P2-02 RCTF

Дополнение по [R.C.T.F.](../practice_02/rctf/experiment.md). Deadline адаптера измеряется монотонными часами, не time.time(). Для транспортного timeout fake HTTP-провайдер откладывает ответ асинхронно на 12 секунд; блокирующий sleep в event loop недопустим.

| ID | Fixture и действие | Ожидаемый результат | Статус |
|---|---|---|---|
| I-REL-01 | Fake не отвечает 12 с; отправить запрос через реальный адаптер с deadline 10 с | 504, error.code=llm_timeout; вызовов 1; транспортное ожидание отменено; слот освобождён; тело не записано в логи | План |
| I-REL-02 | Fake возвращает 503 провайдера | API даёт 502 llm_failed, вызовов 1, retry отсутствует | План |
| I-REL-03 | Fake возвращает JSON с 4 рисками или невалидный JSON | 502 invalid_llm_output; ответ не обрезается до трёх рисков молча | План |
| I-REL-04 | После I-REL-01 переключить fake на корректный ответ и повторить запрос | 200; нет зависшего слота и фонового retry первого запроса | План |

Для стенда допускается до 11 секунд на весь HTTP round-trip; это не увеличение 10-секундного deadline внешнего вызова. Отмена локального ожидания не доказывает прекращения вычисления у внешнего провайдера. Проверка освобождения слота выполняется на клиентской стороне.

## P2-03 Chain of Verification

Уточнения после [CoV](../practice_02/chain_of_verification/experiment.md):

1. I-02 должен доказывать отказ 413 до обращения к LLM, а не обрезку длинного diff.
2. I-03 проверяет удаление секретов. Защита от инструкций внутри diff — отдельная проблема; экранирование не является доказательством её решения.
3. Для OBS-1 проверяется весь настроенный стек логирования на успехе и ошибке. По одному отсутствующему try/except нельзя судить о middleware.
4. Timeout → 504 llm_timeout; сбой провайдера → 502 llm_failed; невалидный результат → 502 invalid_llm_output. Это проектный контракт. 503 busy — локальный отказ при занятом лимите, а не общий код ошибок внешнего LLM.

Для всех этих уточнений runtime-evidence пока отсутствует.

## P2-04 Tree of Thoughts

По [сравнению трёх альтернатив](../practice_02/tree_of_thoughts/experiment.md) выбран локальный fake HTTP-провайдер через настоящий адаптер. Fake Python-объект остаётся для unit-тестов; живой провайдер — только для отдельного согласованного smoke-теста на синтетических данных.

Стенд для интеграции обязан проверять реальные сериализацию запроса, разбор HTTP-ошибки, deadline, число обращений и отсутствие retry. Адрес провайдера переопределяется на loopback; исходящие обращения к внешней модели блокируются в тестовом окружении. Production-ключи не используются.

Проверка выбранного подхода: fake принимает запрос, возвращает 503 → API выдаёт 502 llm_failed; затем fake возвращает валидный JSON → API выдаёт 200; в обоих случаях ровно одно обращение. Отдельно выполняются I-REL-01 и I-REL-04. Наличие локального fake не заменяет проверку очистки секретов и логов.

Выбор proposed: набор тестов не реализован и не запускался.

## P2-05 RAG

Матрица прослеживаемости после [RAG](../practice_02/rag/experiment.md). Все указанные сценарии — планы.

| Правило и источник | Сценарии плана | Что ещё нужно проверить |
|---|---|---|
| [SEC-1](CASE.md#правила-репозитория) | I-03, I-FS-03 | Отдельные fixtures токена, пароля и многострочного приватного ключа; нет исходного значения в HTTP-prompt; число строк сохранено |
| [API-1](CASE.md#правила-репозитория) | I-02, I-FS-01/02 | Unicode-граница; вызовов 0 на 413; 422 — отдельное решение Context Pack |
| [REL-1](CASE.md#правила-репозитория) | I-REL-01/02/04 | Deadline и восстановление; 504/502 и отсутствие retry — проектные решения |
| [OUT-1](CASE.md#правила-репозитория) | I-05, I-REL-03 | Отсутствующие поля, неверные типы, 0/3 риска, несуществующие file/line; schema-valid evidence ещё проверяет человек |
| [OBS-1](CASE.md#правила-репозитория) | I-OBS-01 ниже | Сбор логов middleware, сервиса, адаптера и SDK на всех путях |

I-OBS-01: отправить синтетические маркеры DIFF_TEST_MARKER и RESPONSE_TEST_MARKER; прогнать 200, 413, 502 и 504, затем собрать логи всех включённых слоёв. Во всех событиях разрешены только request_id, duration_ms, status; маркеров и тел нет. Fake хранит синтетический перехват в памяти теста, а не в production-логах. Проверить также исключение провайдера с синтетическим телом в сообщении: тело не должно проникнуть через traceback.

Проверки схемы и экспертиза смысла — разные уровни QA-1; ни один HTTP-статус не доказывает корректность замечания.

## Как использовали AI

- Для чего: подготовка и проверка проектного документа по CASE.md.
- Тип: проектный запрос с ограниченными источниками; OpenCode CLI и редактирование Codex.
- Запрос и ответ: [P1-03](prompts.md#p1-03).
- Проверка Codex: требования сопоставлены с CASE, дополнительные решения помечены, runtime-результаты не выдуманы. Самостоятельная проверка студентом ещё требуется.
