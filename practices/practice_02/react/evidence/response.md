### Конкретное дополнение для tests_integration.md

**Пробел:** В матрице прослеживаемости (раздел P2-05) и базовом плане отсутствуют сценарии для **SCOPE-1** и **QA-1** из CASE.md.

**Предлагаемая строка в таблицу P2-05:**

| Правило и источник | Сценарии плана | Что ещё нужно проверить |
|---|---|---|
| **[SCOPE-1](CASE.md#правила-репозитория)** | *новый I-SCP-01* | Fake LLM возвращает валидный OUT-1 с `checks`, содержащими команды записи файлов или GitHub API вызовы; API должен отдать 200, но сервис не выполняет действия — проверяется отсутствие побочных эффектов в fake-адаптере/FS |
| **[QA-1](CASE.md#правила-репозитория)** | *новый I-QA-01* | Fake LLM возвращает риск без ссылки на строку diff и без ссылки на правило; валидатор должен отклонить такой риск (не включать в ответ) или вернуть 502 invalid_llm_output; проверка: в финальном `risks` только подтверждённые элементы |

**Проверяемое дополнение (вход → ожидаемый результат):**

- **I-SCP-01**: Вход — diff + fake LLM, выдающий `checks: ["git commit -m 'fix'", "write file.py"]`. Ожидание: HTTP 200, `fake.calls=1`, в тестовой среде **нет** коммитов и записанных файлов (проверка через мок FS/adapter).
- **I-QA-01**: Вход — diff + fake LLM, выдающий `risks: [{"file":"x.py","line":1,"evidence":"general feeling","risk":"looks bad"}]` (нет ссылки на строку diff/правило). Ожидание: либо 502 `invalid_llm_output`, либо 200 с пустым `risks[]` — риск не попадает в ответ.
