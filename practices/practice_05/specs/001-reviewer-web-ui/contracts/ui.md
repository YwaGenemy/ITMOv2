# Контракт представления веб-ревьюера

Уточнение реализации `specs/001-reviewer-web-ui/spec.md`, а не новый контракт API. Нормативные поля, пары ошибок и тексты: `specs/contract.md`; базовые требования: `docs/requirements.md`.

## Размещение и отправка

- Готовый `GET /` выдаёт `app/static/index.html`. Весь UI, CSS и JS находятся в этом файле; внешних ресурсов и сборки нет.
- UTF-8, `lang="ru"`, адаптивный viewport. Один заголовок «Ревью изменений», form, видимый label «Diff», textarea, подсказка «Вставьте diff одного PR», submit «Проверить».
- На submit пустого/пробельного поля: «Вставьте diff для проверки», фокус в поле, запросов нет.
- Иначе ровно один `POST /api/reviews`, `Content-Type: application/json`, JSON с единственным полем `diff` и исходным значением поля. Клиент не задаёт request_id/deadline_s и не проверяет длину.
- На время запроса textarea и submit disabled, кнопка «Проверяем…», отдельный статус «Проверяем изменения…». Guard обработчика отклоняет повторный submit.

## Приём и отображение

1. Полностью прочитать и разобрать JSON в пределах общего срока. Сохранить доступный строковый request_id для возможной ошибки.
2. Для HTTP ровно 200 проверить все поля и списки по `data-model.md`. Неверный JSON даёт «Сервис недоступен», разобранный JSON неверной схемы — «Некорректный ответ сервиса».
3. Остальные HTTP-статусы: специальные тексты только для точных пар 422/invalid_request, 413/diff_too_large, 504/llm_timeout, 502/llm_failed из таблицы общего контракта. Корень ошибки и error должны быть объектами, code — строкой; неизвестная/неверная структура, несовпадение пары и ошибка сети дают «Сервис недоступен».
4. При любой ошибке показать доступный request_id отдельным текстом с подписью `request_id`; не выводить error.message, сырой ответ и исключения.
5. Только валидный своевременный успех показывает разделы «Сводка», «Риски», «Проверки». Для каждого риска: «Файл», «Строка», «Фрагмент», «Риск» со всеми значениями. Порядок исходный; ничего не обрезается.
6. Пустые риски: «Риски не найдены»; пустые проверки: «Список проверок пуст». Отсутствие рисков не объявляется гарантией отсутствия дефектов.

## Срок и согласованность

Общий срок — 15 000 мс с начала запроса до готовности результата к публикации, включая чтение body и обработку. AbortController плюс token/settled и абсолютный deadline защищают от поздних ответов. Проверять срок после асинхронных шагов и синхронной обработки, перед изменением UI; `now >= deadline` означает тайм-аут. Текст — «Сервис не ответил вовремя». Любой исход завершает loading и сохраняет поле. Автоповторов нет.

Новая отправка скрывает старый результат и ошибку. Редактирование скрывает только прежний успех; ошибка остаётся до следующей отправки. Перезагрузка открывает пустое начальное состояние. Переходы перечислены в `data-model.md`.

## Текстовый DOM и доступность

- Данные добавляются через textContent/createElement, без innerHTML, Markdown и исполняемых ссылок из ответа. Полный DOM результата готовится после проверки схемы.
- Переносы и отступы evidence сохраняются в pre; длинные пути/строки переносятся или прокручиваются локально, не перекрывая элементы формы.
- Label связан с textarea, подсказка — через aria-describedby. Семантические заголовки и списки, видимый keyboard focus; основной путь доступен Tab и нативным submit.
- Постоянная область role=status объявляет загрузку и успех, role=alert — ошибку; скрытый результат не доступен screen reader. Значение состояния не зависит от цвета.
- При локальной ошибке фокус в textarea; обычный ответ не вызывает принудительного переноса фокуса. Статус находится вне disabled-элементов.
