# Phase 1: данные и состояния UI

Источники: `specs/contract.md` и `specs/001-reviewer-web-ui/spec.md`. Это модель памяти страницы, без БД и новых серверных сущностей.

## Сущности

| Сущность | Поля и ограничения | Связи / срок жизни |
| --- | --- | --- |
| Ввод | `diff: string`; пустота проверяется через trim, передача исходного значения; клиент не ограничивает длину | Одно поле страницы; сохраняется при любом завершении запроса |
| Результат | `summary: string`, `risks: Risk[0..3]`, `checks: string[]`, `request_id: string` | Один полный результат текущей попытки; списки сохраняют порядок |
| Risk | `file: string`, `line: integer >= 1`, `evidence: string`, `risk: string` | Принадлежит результату; все поля обязательны |
| Ошибка представления | Точное русское `message: string`; необязательный `request_id: string`; источник: ввод/API/сеть/схема/срок | Не сосуществует с видимым результатом; не новый API-код |
| Попытка | Уникальный token, снимок diff, `deadlineAt` по монотонным часам, AbortController, timer, settled, доступный request_id | Только одна активная; завершённая не может менять UI |
| Состояние страницы | `input`, `loading`, `success`, `success-empty`, `error`; результат или ошибка по состоянию | Живёт до перезагрузки |

Корень успешного ответа и каждый риск — объекты, не null и не массивы. Проверять типы без преобразования; `line` — через Number.isInteger. Дополнительные поля не отображаются, пустые строки разрешены. `request_id` обязателен как строка в успехе; формат UUID обеспечивает сервер. Из любого разобранного корневого объекта можно извлечь строковый request_id для ошибки независимо от остальных полей.

## Переходы

| Событие | Исходное состояние | Новое состояние / эффект |
| --- | --- | --- |
| Первое открытие / перезагрузка | — | input, пустое поле, без ошибки и результата |
| Submit пробельного/пустого поля | Любое кроме loading | error локального ввода, без fetch, фокус в поле; старый результат скрыт |
| Submit непустого поля | Любое кроме loading | loading; скрыть результат/ошибку, сохранить снимок ввода, заблокировать форму, один fetch |
| Повторный submit | loading | Без изменений и без нового запроса |
| Валидный 200 в срок | loading | success для 1–3 рисков или success-empty для 0; разблокировать форму |
| Ошибка или неверный ответ | loading | error с текстом по контракту; сохранить ввод, разблокировать форму |
| Истёк срок | loading | error «Сервис не ответил вовремя», завершить попытку, abort и разблокировать форму |
| Позднее завершение старой попытки | Любое | Игнорировать, включая старые catch/finally |
| Редактирование diff | success / success-empty | input, скрыть прежний результат |
| Редактирование diff | error | Сохранить ошибку до следующей отправки |

## Инварианты

- Результат публикуется целиком только после проверки схемы и срока. Массив рисков не обрезается.
- Только текущая незавершённая попытка может завершить loading, очистить свой таймер и менять отображение.
- В loading недоступны поле и кнопка; во всех остальных состояниях доступны.
- Ошибка не содержит сырого ответа, исключения или выдуманного request_id. Поздний ответ не дополняет ошибку идентификатором.
- Нет сохранения в браузерное хранилище и логирования diff/ответов.
