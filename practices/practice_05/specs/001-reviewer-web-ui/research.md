# Phase 0: решения для веб-страницы ревьюера

Основания: `specs/001-reviewer-web-ui/spec.md`, `specs/contract.md`, `docs/requirements.md`, конституция, `app/server.py`, `app/llm.py` и текущая HTML-заглушка. Открытых интеграционных вопросов нет; внешние источники и новые зависимости не нужны.

## 1. Стек и границы

- **Decision**: Один `app/static/index.html` со встроенными CSS и JS, нативной form и относительным fetch. Использовать готовые `GET /` и API.
- **Rationale**: Сервер уже читает файл и выдаёт UTF-8; это прямое ограничение человека и принцип I.
- **Alternatives considered**: SPA-фреймворк, сборка, внешние модули и CDN усложняют один экран; новый HTTP-маршрут дублирует фичу 002.

## 2. Единственная отправка и точность ввода

- **Decision**: Один обработчик submit, preventDefault и синхронный guard активной попытки до первого await. Заблокировать поле и кнопку. Проверять `value.trim()` только на пустоту; отправлять исходное value через JSON.stringify, без maxlength и клиентского лимита.
- **Rationale**: disabled-кнопка сама по себе не защищает от повторного submit; длина решается сервером в Unicode code points, а не JS UTF-16 length.
- **Alternatives considered**: Два обработчика click/submit, debounce и клиентская обрезка могут нарушить единственность или исказить diff.

## 3. Полный клиентский срок

- **Decision**: Идентификатор попытки, собственные AbortController и таймер, абсолютный срок `performance.now() + 15000`. Таймер действует до чтения body, разбора, проверки и подготовки результата. Проверять актуальность и срок после await, после обработки и перед публикацией. Завершение допускается один раз; тайм-аут завершает состояние и отменяет запрос. Поздние catch/finally не меняют новую попытку.
- **Rationale**: fetch разрешается при получении заголовков; abort не отменяет уже выполняющееся продолжение. При `now >= deadline` выигрывает тайм-аут, даже если callback таймера задержан.
- **Alternatives considered**: Таймер только до заголовков недостаточен; Promise.race без проверки актуальности допускает поздний результат.

Синхронный JS нельзя прервать таймером на основном потоке: после такой обработки срок повторно проверяется, просроченный результат не публикуется. Физическое объявление состояния происходит при доступности event loop; отдельный worker для этого небольшого интерфейса не вводится.

## 4. Схема и ошибки

- **Decision**: До рендера проверить весь JSON 200: объект, обязательные поля, типы, 0–3 риска, целое line ≥ 1, массив строк checks. Дополнительные поля игнорировать; пустые строки контрактом не запрещены; request_id проверять как строку, без дополнительного regex UUID. Четыре специальные ошибки выбирать только по точной паре статуса и кода.
- **Rationale**: Сервер пока не гарантирует схему модели. Не-JSON 200 — общая ошибка; разобранный JSON 200 неверной схемы — отдельная ошибка ответа. Строковый request_id извлекается независимо от остальной схемы для любой ошибки.
- **Alternatives considered**: Приведение типов, значения по умолчанию, обрезание рисков и серверная US-1 скрыли бы нарушение или расширили область фичи.

## 5. DOM, читаемость и доступность

- **Decision**: createElement/textContent, подготовка полного результата в отсоединённом DOM; evidence как pre, длинные строки с переносом или локальной прокруткой. Label и aria-describedby, постоянные role=status и role=alert, видимый фокус. Ошибка пустого ввода возвращает фокус в поле; завершение запроса не перехватывает его.
- **Rationale**: Разметка в данных остаётся текстом, порядок сохраняется, состояния доступны без цвета и мыши. При редактировании скрывается успех; ошибка остаётся до следующей отправки.
- **Alternatives considered**: innerHTML, Markdown и ссылки из ответа требуют лишней обработки и создают риск исполнения содержимого; одной смены текста disabled-кнопки недостаточно для screen reader.

## 6. Проверка без расширения стека

**Уточнение при реализации по поручению человека (2026-10-27):** разбор ответа и
выбор текста ошибки покрыты исполняемыми JS-тестами без браузера. Существующий
pytest запускает установленный Node.js (`node:test`, `vm`, без npm-пакетов),
читая настоящий inline JS. `sh scripts/check.sh` не меняется. Решение ниже о
только ручной UI-проверке заменено этим уточнением; браузерная интеграция остаётся
дополнительной. Требование Node.js и журнал RED/GREEN указаны в quickstart.

- **Decision**: `sh scripts/check.sh` и браузерные сценарии с FakeLLM и управляемой подменой fetch из `quickstart.md`. Перед кодом зафиксировать RED каждого нового поведения, после — GREEN. Серверные проверки остаются через публичный интерфейс/FakeLLM.
- **Rationale**: pytest не исполняет браузерный JS; зелёная команда сама по себе не доказывает UI. Контролируемые ответы покрывают ошибки и гонки без реального провайдера.
- **Alternatives considered**: Проверки только наличия строк в HTML не доказывают поведение; новая Node/браузерная инфраструктура избыточна для заданного объёма.
