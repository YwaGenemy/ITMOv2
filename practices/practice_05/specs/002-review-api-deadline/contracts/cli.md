# Контракт демо CLI

## Запуск

Из корня проекта `practices/practice_05` в активированной Python-среде:

```sh
python -m app.server PORT --llm ok
python -m app.server PORT --llm slow
python -m app.server PORT --llm fail
```

`PORT` заменяется номером порта. Адрес прослушивания — `127.0.0.1`. Для обратной совместимости позиционный порт необязателен, default `8000`; `--llm` необязателен, default `ok`. Следовательно, `python -m app.server` сохраняет обычный запуск.

Аргументы разбирает stdlib `argparse`; `--help` завершает процесс успешно и описывает порт/режимы. Нецелый порт, неизвестный режим или аргумент дают стандартную ошибку использования и ненулевой выход до запуска HTTP. Порт для обычного демо — 1–65535; порт 0 допустим для выделения ОС в тестах. Дополнительный формат ошибок CLI не является API-контрактом.

## Режимы

| Значение | Адаптер | Допустимый POST |
| --- | --- | --- |
| `ok` | `FakeLLM()` | 200 с DEFAULT_RESULT и серверным request_id |
| `slow` | `FakeLLM(delay_s=12.0)` | 504 llm_timeout примерно после 10 с ожидания, до завершения вызова |
| `fail` | `FakeLLM(error=RuntimeError("demo failure"))` | 502 llm_failed, контрольный текст не возвращается и не логируется |

Неверный вход даёт 422/413 во всех режимах без вызова адаптера. `GET /` выдаёт тот же файл независимо от режима. HTTP-лимит фиксирован в 10 секунд и не настраивается клиентом. Реальные провайдеры и сетевые ключи не нужны.

Адаптер создаётся при запуске и закрепляется за экземпляром сервера. Импорт модуля не запускает сервер и не разбирает CLI. Одновременно запущенные экземпляры могут иметь разные режимы. Остановка демо — Ctrl+C; уже выбранные 504 не ждут окончания daemon-работы.

## Вывод

При обработке ревью выводятся только итоговые сообщения с `request_id`, `duration_ms`, `status`. Содержимое запросов, ответы модели и исключения не печатаются. Стандартные `argparse --help` и ошибки использования относятся к CLI, не к журналу обработки ревью.
