# HTTP и публичная функция

Проектный контракт для реализации [002](../spec.md). Приоритет: [docs/requirements.md](../../../docs/requirements.md); интеграционные решения: [specs/contract.md](../../contract.md). Общий контракт содержит точные тексты и состояния UI.

## GET /

- Тот же `app/server.py`, что обслуживает API.
- Успех: HTTP 200, `Content-Type: text/html; charset=utf-8`, `Content-Length` равен длине тела в байтах.
- Тело: байты `app/static/index.html`. Путь вычисляется относительно модуля, не cwd.
- Файл читается на запрос. Неизвестный GET и отсутствующий файл → 404 без локального пути; формат API-ошибки к этим ответам не применяется.
- Маршрут и минимальная заглушка — команда API; содержимое, CSS и JS — команда UI. При наличии HTML команды UI он сохраняется.

## POST /api/reviews

Запрос: `Content-Type: application/json`, JSON-объект `{"diff":"..."}`. Длина строки 1–20 000 Unicode code points после декодирования; пробелы допустимы. Тело не обрезается, синтаксис unified diff не проверяется. Клиент не управляет лимитом и идентификатором через дополнительные поля.

HTTP читает тело, вызывает `handle_review(body, server_llm, deadline_s=10.0)` и передаёт возвращённые статус и JSON-payload. Ответ: `Content-Type: application/json; charset=utf-8` и точный `Content-Length`. Неизвестный POST → 404.

### Успех

HTTP 200. Пример ожидаемого корректного результата:

```json
{
  "summary": "Изменение проверено",
  "risks": [],
  "checks": [],
  "request_id": "f7a5cd9283104ef6a72560aa8cc44701"
}
```

Сервер добавляет собственный идентификатор к словарю модели, не проверяя схему и не сокращая риски. Ожидаемые поля риска и правила UI — в [модели данных](../data-model.md) и общем контракте. Неверная схема JSON 200 или >3 риска отклоняются UI; кода `invalid_llm_output` здесь нет.

### Ошибки

Точная форма для всех четырёх ошибок:

```json
{"error":{"code":"llm_timeout"},"request_id":"f7a5cd9283104ef6a72560aa8cc44701"}
```

| HTTP | `error.code` | Условие | Вызовы LLM |
| --- | --- | --- | --- |
| 422 | `invalid_request` | Неверный JSON, не объект, нет diff, неверный тип или пустая строка | 0 |
| 413 | `diff_too_large` | Строка >20 000 code points | 0 |
| 502 | `llm_failed` | Исключение адаптера до истечения срока | 1 |
| 504 | `llm_timeout` | Вызов не завершён своевременно | 1 |

У ошибок нет `message`, успешных полей или внутренних сведений. Идентификатор создаётся до разбора JSON. При любом исходе повторов нет. Поздний успех/сбой не меняет 504. Стандартный access log подавлен; HTTP не создаёт вторую запись результата. Ожидаемый разрыв соединения при отправке не меняет выбранный результат и не выводит traceback.

## Серверная точка входа

`app.review.handle_review(body: bytes, llm, *, deadline_s=10.0) -> tuple[int, dict]`.

`llm.review(diff: str) -> dict` — синхронный интерфейс существующего `LLMClient`. `deadline_s` — положительный серверный параметр. Отсчёт ожидания начинается после валидации, непосредственно перед запуском работы. Функция не ждёт завершения после выбора 504. Физическая отмена вызова не гарантируется. Исключение адаптера преобразуется в безопасный отказ; позднее исключение перехватывается без диагностики.

Любой контрактный исход содержит серверный uuid4 hex и одну запись `request_id`, `duration_ms`, `status` до возврата функции. Лог измеряет логику, не чтение HTTP-тела и не подтверждение сетевой доставки.

## Стык с UI

- Один origin, относительный `POST /api/reviews`; CORS не требуется.
- Сервер ждёт LLM 10 секунд, UI ограничивает весь запрос 15 секундами.
- UI определяет известную ошибку по совпавшей паре HTTP и `error.code`, показывает доступный `request_id`, не выводит сырой ответ.
- Автоматических повторов нет. Сервер не реализует клиентские состояния или 15-секундный таймер.
- Ошибки/тексты, схема отображения и защита от позднего клиентского ответа определены общим контрактом D1–D6.
