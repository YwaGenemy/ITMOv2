# Модель данных: 002-review-api-deadline

Нормативные источники: [spec.md](spec.md), [requirements](../../docs/requirements.md), [общий контракт](../contract.md). Постоянного хранилища нет.

## Запрос ревью

| Поле / значение | Тип | Правило |
| --- | --- | --- |
| `body` | bytes | Исходное JSON-тело публичной функции |
| декодированное тело | object | Массивы, null и скаляры → 422 |
| `diff` | str | Обязателен, длина 1–20 000 Unicode code points |

Ошибка JSON, отсутствие/нестроковый/пустой `diff` → 422 `invalid_request`; превышение длины после проверки типа → 413 `diff_too_large`. Пробелы допустимы. Дополнительные поля не вводят новых правил и не управляют `deadline_s` или `request_id`. В LLM передаётся ровно исходная декодированная строка, без нормализации.

## Контекст обработки и конфигурация

| Поле | Тип | Назначение |
| --- | --- | --- |
| `request_id` | str | Генерируемый сервисом uuid4 hex, 32 hex-символа без дефисов |
| начало обработки | monotonic float | Измерение длительности логики |
| `deadline_s` | positive float | Параметр сервера, default 10.0; HTTP всегда 10.0 |
| абсолютная граница вызова | monotonic float | Вычисляется после валидации перед запуском вызова |
| `llm` | LLMClient | Один вызов `review(diff)` при допустимом входе |

Контекст принадлежит одному запросу. Клиент не задаёт идентификатор. Семантика неположительных/нечисловых значений лимита не входит в контракт этой фичи.

## Внутренний исход зависимости

Локальное сообщение очереди: признак успеха или сбоя, монотонное время завершения, словарь результата только при успехе. Объект исключения не сохраняется в сообщении. Это внутренняя структура, не HTTP-поле и не сущность хранилища.

Один запрос связан максимум с одним вызовом и одной публикацией исхода. При 504 очередь может получить позднее сообщение; это не создаёт повторной обработки или записи лога.

## Результат ревью и риск

| Поле | Ожидаемый тип по общему контракту |
| --- | --- |
| `summary` | str |
| `risks` | array объектов риска |
| `checks` | array строк |
| `request_id` | str, серверный uuid4 hex |
| `risks[].file` | str |
| `risks[].line` | int ≥ 1 |
| `risks[].evidence` | str |
| `risks[].risk` | str |

Результат содержит ноль или несколько рисков и проверок. UI принимает 0–3 риска; пустые списки допустимы. Сервер в этой фиче **не валидирует** типы полей модели и число рисков: своевременный словарь передаётся как 200 с серверным `request_id`, включая некорректную схему или более трёх рисков. Указанные типы — контракт отображения, не новый серверный gate. Поведение произвольного несловарного возврата адаптера не расширяется: `LLMClient.review` объявлен возвращающим dict.

## Ошибка обработки

Точная структура: `{"error":{"code":"..."},"request_id":"..."}`.

| `error.code` | HTTP | Основание |
| --- | --- | --- |
| `invalid_request` | 422 | JSON/объект/тип/непустота |
| `diff_too_large` | 413 | Длина >20 000 |
| `llm_failed` | 502 | Своевременное исключение адаптера |
| `llm_timeout` | 504 | Нет своевременного завершения вызова |

В `error` только `code`, на верхнем уровне только `error` и `request_id`. Нет `message`, результата, текста/типа исключения или traceback.

## Наблюдаемость

Одна итоговая запись на вызов `handle_review` с контрактным исходом:

| Поле | Тип | Правило |
| --- | --- | --- |
| `request_id` | str | Совпадает с ответом |
| `duration_ms` | int ≥ 0 | Время обработки логики до возврата, миллисекунды |
| `status` | int | Совпадает с возвращённым HTTP-статусом |

Diff, модельный ответ и исключения не включаются. Запись принадлежит логике; HTTP и фоновая работа её не дублируют. GET и неизвестные маршруты не являются обработкой ревью и не создают такую запись.

## Страница и демо-конфигурация

- Страница — байты `app/static/index.html`, выдаваемые без преобразования. Файл не содержит данных конкретного ревью и не является хранилищем запросов.
- Конфигурация процесса: `port` (default 8000), `llm_mode` (`ok`, `slow`, `fail`; default `ok`). Адаптер создаётся при запуске и принадлежит серверу. Соответствие режимов зафиксировано в [CLI-контракте](contracts/cli.md).

## Переходы обработки

```text
начало → request_id + начало измерения → проверка JSON/входа
  ├─ неверная структура/тип/пустота → 422
  ├─ длина >20 000 → 413
  └─ допустимо → один вызов LLM + ожидание до границы
                  ├─ своевременный успех → 200
                  ├─ своевременное исключение → 502
                  └─ истечение ожидания → 504
любой выбранный исход → один итоговый лог → возврат
поздний исход после 504 → только завершение фоновой работы
```

Все возвращённые исходы окончательны. Время на границе не требует отдельного клиентского состояния; повторов нет.
