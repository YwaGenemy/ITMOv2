# Implementation Plan: Ограниченное ожидание LLM в API ревью

**Branch**: `002-review-api-deadline` (идентификатор из setup-plan; фактическая Git-ветка `practice_05`) | **Date**: 2026-10-27 | **Spec**: [spec.md](spec.md)

**Input**: `specs/002-review-api-deadline/spec.md`, [specs/contract.md](../contract.md), поручение о D1 и демо `python -m app.server PORT --llm ok|slow|fail`.

## Summary

Сохранить фичу A и ограничить ожидание единственного синхронного вызова LLM: 10 секунд по умолчанию, положительный серверный `deadline_s` для прямых вызовов. Отдельный daemon-поток и локальная очередь позволяют вернуть 504 `llm_timeout` без ожидания завершения; своевременное исключение даёт 502 `llm_failed` без диагностики. Все исходы получают uuid4 hex и одну запись только с `request_id`, `duration_ms`, `status`.

HTTP транслирует результат логики. Эта фича также выдаёт `app/static/index.html` по `GET /` (D1) и добавляет CLI-режимы `FakeLLM`: обычный, задержка 12 секунд и исключение. HTML первоначально — заглушка; содержимое и клиентское поведение создаёт команда UI. Проектные решения и альтернативы: [research.md](research.md).

## Technical Context

**Language/Version**: Python 3.10+; текущая среда 3.14.6. HTML UTF-8 для заглушки.

**Primary Dependencies**: только stdlib: `threading`, `queue`, `time`, `json`, `uuid`, `logging`, `http.server`, `pathlib`, `argparse`; существующий `FakeLLM`.

**Storage**: БД нет; файл `app/static/index.html`; локальные объекты запроса и очереди в памяти.

**Testing**: pytest из существующей среды; единственная команда `sh scripts/check.sh` (compileall + pytest). При реализации — skill `test-driven-development`, сначала подтверждённое падение. Адаптер в тестах — только `FakeLLM`.

**Target Platform**: локальный Python-сервер на Linux, `127.0.0.1:PORT`, браузер на том же origin.

**Project Type**: небольшой HTTP-сервис с модульным CLI и статической страницей.

**Performance Goals**: SC-001 — при `deadline_s=0.1`, задержке 1 с возврат 504 не позднее 0,5 с. HTTP лимит — 10 с ожидания LLM, UI лимит — 15 с всей операции. Допуск теста не расширяет рабочий лимит.

**Constraints**: ≤20 000 Unicode code points после JSON-декодирования; ноль вызовов при отказе, один при допуске; без повторов, trim и усечения. Только три поля логов. Схема результата модели и US-1/US-2 не реализуются. Deadline не включает чтение HTTP-тела и доставку ответа; физическая отмена адаптера не требуется.

**Scale/Scope**: один учебный сервис, два маршрута и три демо-режима; без требования к throughput. Один daemon-поток на допустимый запрос; незавершённые вызовы удерживают ресурсы до своего завершения.
