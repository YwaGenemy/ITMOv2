# Исследования: 002-review-api-deadline

**Дата**: 2026-10-27. Основание: [spec.md](spec.md), [общий контракт](../contract.md), [требования](../../docs/requirements.md), конституция 1.0.0 и текущие `app/review.py`, `app/llm.py`, `app/server.py`.

## R1. Ограниченное ожидание синхронного адаптера

**Decision**: после валидации запускать единственный `llm.review(diff)` в `threading.Thread(daemon=True)`. Результат передавать через локальную `queue.Queue(maxsize=1)`. Использовать абсолютную границу `time.monotonic() + deadline_s` и ждать только оставшийся бюджет. Сообщение очереди содержит признак успеха/сбоя, результат при успехе и монотонное время завершения. Исключение адаптера перехватывается в рабочем потоке как `Exception`; его объект, тип и текст не передаются и не логируются. Не вызывать `join` после таймаута.

**Rationale**: публичная функция остаётся синхронной; 504 возвращается без ожидания завершения зависимости. Поздняя единственная публикация помещается в очередь без потребителя; рабочий поток не имеет доступа к выбранному ответу и не пишет лог. Время завершения позволяет отклонить явно запоздавший результат даже после задержки планирования основного потока. `queue.Empty` либо завершение после границы дают 504; своевременный сбой — 502. Повторов нет.

**Alternatives considered**: `ThreadPoolExecutor` в `with` отклонён из-за `shutdown(wait=True)` при выходе; `shutdown(wait=False)` не устраняет ожидание потоков executor при завершении интерпретатора. Общий пул вводит очередь задач и проблему занятых зависшими вызовами слотов. `signal` не подходит для потоков HTTP-сервера; отдельные процессы усложняют передачу адаптера и наблюдение `FakeLLM.calls`.

**Граница решения**: это ограничение ожидания, а не физическая отмена вызова. До завершения зависимость удерживает поток и данные; число зависших операций не ограничивается этой фичей. Строгий порядок одновременных событий на границе и неверные значения серверной конфигурации не определены спецификацией. Приёмка использует положительный `deadline_s` и конечные задержки.

## R2. Валидация и успешный результат

**Decision**: сохранить текущий порядок JSON → объект → непустая строка → `len(diff) <= 20000`. Строку передавать без изменений. Своевременный словарь адаптера объединять с серверным `request_id`, как сейчас; проверку полей результата и обрезание рисков не добавлять.

**Rationale**: Python `len(str)` считает Unicode code points после JSON-декодирования. Требования не требуют синтаксиса unified diff и разрешают пробельную строку. D3 относит проверку результата для отображения к UI. API-поля клиента не управляют лимитом или идентификатором.

**Alternatives considered**: подсчёт UTF-8 байтов/UTF-16 единиц, `strip`, усечение входа, серверная проверка схемы и новый код `invalid_llm_output` меняют согласованный контракт.

## R3. Единая наблюдаемость

**Decision**: перенести владение итоговой записью из HTTP в `handle_review`. Начать измерение при входе, создать uuid4 hex, сформировать исход и один раз перед возвратом записать сообщение с полями `request_id`, `duration_ms`, `status`. Использовать существующий logger `reviews`; конфигурацию вывода оставить в `main`, формат — только сообщение. Ошибки строить через общий `_error_response`.

**Rationale**: все исходы, включая неверный JSON и 504, проверяются через публичную функцию. Запись отражает завершение логики, не подтверждение доставки HTTP. Фоновая работа не создаёт вторую запись после таймаута. Полезные поля сообщения следует отличать от служебных атрибутов стандартного `LogRecord`.

**Alternatives considered**: только HTTP-лог не покрывает прямые вызовы; лог в обоих слоях дублирует запись; callback фоновой задачи меняет наблюдаемость после 504. Стандартный access log остаётся подавленным. Ожидаемый разрыв соединения при записи HTTP-ответа обрабатывается без traceback и повторного логирования результата.

## R4. GET / и принадлежность файла

**Decision**: оставить `ThreadingHTTPServer`; добавить в `app/server.py` точечную выдачу `/` из `Path(__file__).resolve().parent / "static" / "index.html"`. Отправлять байты файла, 200, HTML UTF-8 и точный Content-Length. Неизвестный GET и отсутствие файла дают 404 без раскрытия локального пути. При реализации создать минимальную HTML-заглушку, если файл ещё отсутствует; существующий файл UI не перезаписывать.

**Rationale**: D1 назначает маршрут команде API, содержимое — UI. Путь не зависит от рабочего каталога; чтение файла на запрос позволяет подставить результат команды UI без изменения Python.

**Alternatives considered**: `SimpleHTTPRequestHandler` открывает лишнюю поверхность файловой выдачи; встроенный в Python HTML создаёт второй источник страницы; относительный путь зависит от cwd.

## R5. CLI для демонстрации

**Decision**: `argparse`, синтаксис `python -m app.server PORT --llm ok|slow|fail`; сохранить значения по умолчанию PORT=8000 и режим `ok`. Режимы: `ok` → `FakeLLM()`, `slow` → `FakeLLM(delay_s=12.0)`, `fail` → `FakeLLM(error=RuntimeError("demo failure"))`. Значения выбираются один раз при запуске и привязываются к экземпляру сервера, а не к изменяемому глобальному адаптеру. HTTP всегда вызывает логику с `deadline_s=10.0`; адрес — `127.0.0.1`.

**Rationale**: существующий `FakeLLM` уже умеет задержку и исключение; расширять адаптер не требуется. 12 секунд превышают серверные 10 и позволяют демонстрировать 504 до клиентских 15. Изоляция адаптера на экземпляр сервера упрощает HTTP-тесты.

**Alternatives considered**: режим в теле POST делает серверную конфигурацию клиентской; глобальное переназначение `LLM` связывает тесты; реальные провайдеры нарушают воспроизводимость. Новые переменные окружения и зависимости не нужны.

## R6. Среда и проверка

**Decision**: Python 3.10+ (синтаксис существующего проекта), текущая среда Python 3.14.6; в `app/` только stdlib. Тесты — существующий pytest через `sh scripts/check.sh`, без новых зависимостей. Применять TDD при последующей реализации: падающий тест → минимальный код → зелёная проверка.

**Rationale**: конституция и style guide задают публичную точку `handle_review` и только `FakeLLM`. Для SC-001: лимит 0,1 с, задержка 1 с, возврат ≤0,5 с. Для поздних исходов дождаться конечной задержки и проверить неизменность ответа, единственный вызов/лог и отсутствие необработанного исключения. HTTP проверяется loopback-сервером на порту 0 и stdlib-клиентом; отсутствие сети означает отсутствие внешних сервисов, не запрет локальной HTTP-приёмки.

**Alternatives considered**: точное равенство длительности deadline делает тест хрупким; проверка внутренних очередей не доказывает контракт; повторные 10-секундные ожидания во всех unit-тестах избыточны. Рабочие 10 секунд проверяются в отдельном демо-сценарии, быстрые тесты используют серверное переопределение и проверяют передачу 10.0 HTTP-слоем.
